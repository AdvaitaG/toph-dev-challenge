# Employee activity flow

Visitors can create an employee account at `/signup` using email or Google. Supabase Auth handles the credentials; an `auth.users` trigger creates a Bays Ranch `employees` row and a same-farm `profiles` row with the `employee` role for each new email-bearing Auth user. The server routes managers to `/` and employees to `/employee`. The existing confirmed manager account keeps its profile when Google links the same verified email. A confirmed Anthony Wells demo account is also linked to the existing Anthony worker record, preserving the 12-worker seed snapshot.

The linked project's confirmation-email Site URL is currently `http://localhost:3000`. Keep `npm run dev` running on the same computer/browser when opening that link. The root route exchanges the one-time PKCE code into a cookie-backed session and sends the employee to `/employee`; if the exchange cannot finish, the login page explains how to continue. Confirmation can succeed even if the final localhost page cannot load, so an already confirmed employee should sign in rather than create the account again. Before public deployment, change the Supabase Auth Site URL and redirect allow list to the deployed HTTPS origin.

The employee form submits a field, activity, farm-local work date and time range, plus a written note or voice clip. Written-only submissions use the Server Action and create an unscored pending `activity_logs` row without a recording. Voice submissions record up to 90 seconds in the browser, offer an editable browser-generated transcript where speech recognition is supported, and allow an optional note. The authenticated route uploads audio to the private `toph-recordings` bucket, then calls the `submit_recorded_activity` database function to create the log and recording rows atomically. The function derives farm, employee, and submitter IDs from the verified session and runs under RLS. Employees can read their own submissions; a manager sees them through the existing dashboard query and can play the audio through a one-hour signed URL. The dashboard's Figma styling and serializable `DashboardData` contract remain intact. The April 22, 2026 seed recordings remain demo snapshot data.

Managers can add reusable tags and remove an employee-submitted log from its expanded row. Both the action and RLS require same-farm manager access, and deletion requires `submitted_by IS NOT NULL`. Seeded Figma rows have no submitter and cannot be removed through this flow. Deleting a log cascades its tag assignments and recording metadata; the action then removes its stored audio object. Tag definitions remain reusable.

The version-controlled changes include `supabase/migrations/20260917000000_employee_activity_flow.sql` through `20260917050000_employee_voice_recordings.sql`. `supabase/admin/provision_anthony_demo.sql` links the approved demo identity to the existing worker. The public signup trigger intentionally assigns every new email account to Bays Ranch: suitable for this single-farm challenge demo, but a real multi-farm launch would need an invitation or farm-selection approval flow and signup abuse controls. Email confirmation follows the linked project's Supabase Auth setting.

Verification: local SQL tests exercise role/farm isolation, forged signup metadata, employee insert, voice recording creation, manager visibility/deletion, and seeded-row protection. Browser tests exercise signup, voice capture/transcription/submission/refresh, manager playback, role routing, and manager removal. `scripts/verify-employee-live.mjs` checks written submissions and tags; `scripts/verify-voice-live.mjs` generates a short clip, uploads it with an employee session, verifies manager signed playback, then removes its log and audio. Both require credentials through environment variables and never store passwords in the repository. Automatic transcription uses the browser's speech recognition API, so availability varies by browser; employees can always type a transcript or submit a written note.
